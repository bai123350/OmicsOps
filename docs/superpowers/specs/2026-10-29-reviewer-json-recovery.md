# Reviewer 在当前步骤修复 JSON 格式

## 故障与范围

本次截图运行持续 18 分 33 秒。只读事件元数据确认主执行已经提交完成提案，
确定性验证完成后进入独立 Reviewer；约三分钟后第一次 malformed JSON 触发
整轮再生，再过约三分钟第二次 malformed JSON 使运行失败。44 条已完成工具
记录保留，没有 ReviewerFinished。当前没有存活进程，不能仅凭运行晚于安装包
时间就断言用户当时使用了哪个二进制。

原核心层只再次调用相同 review(request)，桌面层重新创建快照窗口和读取计数，
模型没有收到前一次格式错误的修复指导。主执行截断修复不覆盖这一条路径。

## 决策

桌面 Reviewer 在发生明确的参数 JSON 错误、输出截断或报告 schema 错误时，
整体丢弃当前响应，在当前步骤使用一次精简重生成。保留已冻结证据、已准入页面、
覆盖范围、读取计数与当前工具集合；添加宿主固定的严格 JSON 格式指导，不回传
坏参数、部分正文、私有推理或错误原文。报告必须由模型重新完整生成，宿主不能
猜补引号、拼接参数、默认填写报告或自动通过审查。

一次运行时恢复状态由核心创建，在端口和选定的独立 Reviewer 之间传递，并在
格式错误、网络重试和空闲超时重试之间共享。该状态不进入 JSON/数据库或模型
上下文。旧端口默认方法保持兼容，外层旧格式恢复和桌面步骤内恢复共用一个名额。

同一逻辑审查最多八个步骤和一次格式替代请求，读取仍最多十六次和 96 KiB；
最后一步的修复仍只允许提交报告。128 KiB 上下文限制、实际 provider wire 预算、
180 秒无有效输出超时与整个审查 900 秒上限保持。格式指导也计入请求预算。
格式指导不会刷新有效输出计时。停止/取消仍由外层监督。

证据哈希不一致、伪造引用、越权工具和非法工具批次不进入格式修复。连续错误
用固定耗尽分类结束，不通过错误恢复获取额外能力，不重新执行主执行工具。
独立报告仍验证字段、引用和部分证据限制；恢复成功不代表科研结论自动通过。

## 验证计划

真实 provider 解析夹具先复现坏 JSON 报告失败，再验证读页后修复保留原页、
完整输入和能力；参数及错误原文不进入替代请求。覆盖混合输出错误共用一个
名额、最后一轮 submit-only、完整 wire 预算拒绝、跨 transport/idle 重试额度，
并保留取消、时间预算、来源完整性与报告限制测试。

默认完整验证和 Windows 打包后填写实际结果。真实模型、SSH、科研任务端到端
和安装升级需单独验收；本次离线测试不等于这些流程已通过。
