# 推理强度与模型输出预算

## 问题

OpenCode Go 的 deepseek-v4.1-flash 在完成工具发现后返回输出截断。当前精确模型
目录的 context/output 上限分别是 1,000,000/384,000；用户选择 max 推理强度，但
请求固定携带 max_tokens=16,384。推理与工具参数共用输出额度，该本地预留没有随
高推理强度调整。前一成功请求的 5,357 个输出 token 中包含 4,884 个推理 token；
截断请求没有最终用量记录，因此不能声称其具体推理 token 数已测得。

## 修改

仅对已有精确可信目录且 reasoning=true 的配置调整请求预留：high 为 32,768，
max/xhigh/ultra 为 65,536，其他强度保留 16,384。以上是应用的有界请求预算策略，
不是模型能力推断；最终值继续不超过目录 output_limit 和有效上下文的一半。
未知模型及不支持推理的模型继续使用原先的 4,096 规则，不根据家族名、前缀或
未知网关猜测能力。模型目录保持原样。

较高预算允许提供方生成更长回复，可能增加单次延迟和用量；它是上限而不是强制
生成长度。仍可能遇到提供方限制或更长输出，不能保证任何对话都不再截断。

实际输出预算参与 execution_configuration_hash。原冻结运行的配置身份不改写、
审批不绕过；改变预算后的新运行冻结新配置。历史失败保留，用户在原会话发送
“继续”创建新运行。自动继续的默认设置和次数保持原样，截断工具调用绝不执行。

## 验证

先用失败回归证明 max 请求仍错误限制为 16,384，再验证修复后值贯穿核心配置、
桌面组合和实际 OpenAI 兼容请求体。覆盖目录输出上限、小上下文、未知模型、
非推理模型、各强度及配置哈希。完整确定性检查后，使用一次性项目和只读用户
配置执行精确 DeepSeek 模型的 OpenCode ignored 验收；真实凭据只从系统钥匙串读取。
该验收仅覆盖模型—文件读取—模型完成，不等同于原 miRNA 文献流程验收。
