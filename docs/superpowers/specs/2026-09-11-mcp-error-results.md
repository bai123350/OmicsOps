# MCP 参数错误作为失败结果

## 问题与边界

实际运行中 PubMed 查询长 603 字符，超过 500 字符限制。服务端返回
JSON-RPC `-32602`，客户端却把所有 `ServiceError` 都映射为 Transport，
上层因此记录副作用不确定并要求用户核实。

## 行为

- `ServiceError::McpError` 是服务器已明确回复的失败，转换为 MCP
  `isError: true` 工具结果，保留错误码及说明；会话保持可用，不自动重试。
- PubMed 搜索和抓取的业务参数校验返回失败工具结果；查询 schema 声明
  1–500 字符限制，运行时按 Unicode 字符计数并拒绝控制字符。
- 已批准的内置 PubMed 配置若缺少查询约束，在工具目录发现时重新检查内置
  服务器并刷新目录。冻结的 schema/catalog 校验与审批边界保持有效。
- 历史 MCP `tool_dispatch_uncertain` 事件在界面呈现为失败，移除副作用核实
  表单，停止显示该调用仍在执行。历史事件链不改写，不因此自动重试。
- 真正的传输中断、超时与远端计算派发仍保留原始错误与恢复语义；不能把
  未收到结果解释为远端操作未执行。非 MCP 的远端副作用核实入口保留。

## 验证

- 独立 MCP 测试进程先返回 `-32602`，随后成功执行更正后的调用：失败结果
  可读，进程只启动一次。
- PubMed 超长、空和含控制字符的查询均无需联网即可返回失败结果；覆盖
  schema 与 Unicode 长度边界。
- 前端回归覆盖旧 MCP 错误不显示核实表单、显示失败，以及远端计算核实
  入口仍可用。
- 手工 smoke：在一次性项目中提交超长查询，再提交合法查询，确认失败
  说明可见且后续调用可执行。完整真实模型 Agent 验收另行记录，测试替身
  与构建不等同于端到端科研任务成功。
