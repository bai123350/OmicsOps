# 评审请求超限与文件树名称修复

## 复现与原因

文献调研运行在完成提议及确定性核验后失败，报 provider JSON 的保守 UTF-8
字节估算为 2,530,523，加输出预留与余量后超过 1,000,000 的窗口。该数值不是
服务端实际 token 消耗；当前模型为普通 HTTP 路由，不应归因于 native replay。

执行请求已有上下文投影与压缩，而 Desktop Reviewer 把完整 ReviewerRequestV4
直接序列化后发送。其 verified_evidence 包含原始事件，scientific_state 也完整
复制，绕过执行期的有界投影。故障事件元数据中存在约 607 KB、532 KB 的工具
结果，以及完成提议、确定性核验，但没有完成的 Reviewer 报告，与该入口吻合。
界面 9% 来自此前执行请求的 provider 用量；评审没有记录同一类用量事件。

文件树另有独立 CSS 问题：全局 input 宽度与 padding 应用到了基线复选框，
复选框挤掉 flex 文件名区域；无复选框的目录仍能显示名称。真实浏览器中，
400 px 栏宽的文件名为零宽，而复选框占 97–193 px。

## 修复范围

保持核心 ReviewerRequestV4、确定性核验、原始持久化证据、模型精确目录和发送
预算校验不变。桌面评审层将本次请求保存在私有冻结快照中，提供有界证据目录、
源引用、字节数与摘要哈希；需要细节时，仅通过本轮专属只读分页接口按 JSON
指针检索该快照。目录或省略标记不等于已经审阅完整证据。

读取接口不调用执行 ToolRegistry、不读取项目文件、SSH、MCP 或其他运行。
限制每页、累计读取、轮数及实际 provider JSON；未知引用、哈希不符、非法
偏移或范围拒绝。混合读取与提交、多次提交或未知工具拒绝，最终报告仍需符合
原 schema 和冻结证据引用约束。关键证据缺失时不得直接以空 findings 声称全部
核验通过。重试沿用相同冻结内容，不重跑原始工具。

文件树仅局部约束复选框尺寸和 flex 行为，为文件名保留宽度；深层窄栏采用
紧凑缩进，长名可省略并保留完整 title/可访问名称，不改全局表单 input。

本轮不扩展 native replay 压缩，不更改审批、执行身份、数据位置或 SQLite
模式。定位时仅读取当前模型协议/域名及故障事件类型/字节长度，测试使用合成
证据，不把用户聊天、工具原文或凭据放入 Git、安装资源或测试夹具。

## 验证与实施顺序

1. 先以合成大型工具证据和科学状态复现 Reviewer 超预算，再验证有界初始
   请求及分页后的实际 provider 预算、引用校验、读取限额与提交规则。
2. 验证冻结源、重试、取消与无副作用边界；保持原始核心证据完整性测试。
3. 用真实浏览器布局复现及验证文件名非零宽，覆盖约 400 px、260 px 侧栏与
   深层长文件名，并保留原文件操作及复选框测试。
4. 执行 Web 构建、Rust workspace、前端全套和 Windows 桌面构建及隐私检查；
   独立审查后按评审预算、文件树和文档提交。不创建 tag 或更新 GitHub Release。

真实模型/SSH、科学结论及原生安装升级验收需另在一次性环境中执行，不能由
模拟传输、浏览器布局测试或成功打包替代。

## 来源读取契约回归

后续运行报 `reviewer_read_source_mismatch`。该错误说明当前来源 ID 存在，
且快照校验已通过，但模型回填的来源哈希缺失或不匹配，不能据此断言冻结
内容已经变动。旧目录只给被省略的大来源附读取元数据，inline 来源及固定字段
仍注册为可读，却没有提供其读取所必需的哈希。另有来源哈希与所选子树的内容
哈希同时出现，容易混用；一次参数错误又通过 `?` 直接终止整次评审。

修正此私有接口：读取参数只包含当前 review 内的短 `source_id`、JSON pointer、
offset 和 limit；完整来源目录与工具 schema 的 ID 枚举从同一冻结快照产生。
哈希作为输出审计元数据保留，完整性由宿主核验，不再要求模型抄写两个长摘要。
source_id 仅查询本次 owned Snapshot 的局部 map，不查询其他运行、项目、文件
或服务。同名局部 ID 不意味着可以跨快照读取。

未知 ID、页参数或额外字段等协调错误返回有界、无原始 payload 的读取结果，
要求模型在同一快照中显式纠正；错误也消耗尝试/轮数预算，不增加读取覆盖率。
真正内部完整性失败和预算耗尽仍终止，原执行工具不重跑，未完整读取的提示与
最终模型请求预算保持。测试必须从模型实际可见的目录/工具 schema 取得参数，
不能从私有 Source map 偷取哈希而掩盖接口不可用的问题。

本轮实测：目录驱动的 inline 读取回归在旧实现先失败，修复后
`cargo test -p omicsops-desktop --lib reviewer_` 25 项全部通过。覆盖 inline
来源、子树后续页、旧哈希额外字段/非法指针后的显式纠正与提交、反复错误消耗
16 次尝试、错误不增加覆盖率、嵌入伪造元数据、不同 Snapshot 同名 ID 隔离、
宿主内部值/摘要篡改拒绝，以及既有实际 HTTP 预算与部分审查提示。

`npm run build`、`npm test` 通过：132 文件、1587 项，另有扩展 22 项和发布
脚本 37 项。`cargo test --workspace` 为 2107 通过、22 ignored、零失败。
全局格式检查通过，独立源码复核没有发现阻塞。该轮未读取真实 API key、
运行真实模型或访问 SSH；25 项测试与全套检查均使用离线夹具。
`npm run build:desktop` 通过，生成新的本地 Windows x64 EXE/MSI，配置资源、
Web 与原生二进制隐私检查通过。没有安装本轮包或更新 GitHub Release；现存
失败记录不改写，需在安装重启后重新尝试。实现/回归与验证文档分组提交。

## 多轮分页工作集预算回归

用户确认 402 是 API 余额不足；本轮处理的新错误为
`reviewer_context_budget_exceeded`，没有继续混入计费 UI 变更。旧实现在首轮
拟合成功后，每轮都重新发送 `initial + 全部历史 pages`，没有为后续结果预留
空间。约 105 KiB 的合法固定提议加 4 个 8 KiB 页面即可超过 128 KiB，JSON
转义会再扩大页面；较小模型还可能先触及实际 provider 预算。读取额度 96 KiB
和初始上下文额度不能各自独立使用。旧 read 在页面被下轮准入之前就记录范围，
也会把尚未送达模型的字节误记成已读。

修复为统一的逐轮 render/admit：保留完整固定合同与冻结来源目录，先缩减
可选预览，再沿 UTF-8 边界缩小新页，准确返回实际 next_offset。准备页不增加
覆盖率；只有页进入准入请求后才提交实际范围和字节记账。重复的相同来源、
指针和偏移页面合并，保留较长已呈现内容；不同原始证据不静默驱逐。控制错误
仅保留最新一条。宿主原文、摘要和来源绑定保持不变。

初始准入预留最小页面与有界控制反馈。没有更多空间、读取额度耗尽或到达
最后可用模型轮次时，关闭后续读取，仍要求模型基于已有证据显式提交真实的
部分评审，不自动产出通过报告。未交付或延后的字节不增加已读覆盖率，省略
限制提示保留；不增加 128 KiB、模型窗口、读取额度或轮数上限。真正固定合同
连控制空间都容不下时，在首轮前明确拒绝；未知工具、混合提交、完整性错误
仍按既有边界拒绝。

原错误已由离线真实评审循环复现：105 KiB 完整提议 + 四个含引号、反斜杠、
中文和 emoji 的 8 KiB 页，在旧实现第二轮前报同一错误；修复后该场景通过。
准入与发送复用同一 request 构造函数；页面按实际末端/文本区间识别重复和前缀
扩展，已交付区间只记新增字节，所有尝试仍计数。缩页会尝试首个完整 UTF-8
字符，避免 7 字节请求折半时跳过可容纳的 4 字节字符。部分评审给宿主限制提示
