# 审查证据正文去重

## 问题与行为

materialize_verified_evidence 原来遍历每个完成条件的引用，逐项展开全文。
同一工具事件、产物或科研证据支持多个条件时，审查请求会多次传输相同正文。
本次按引用类型和精确标识去重，保持首次出现的顺序。完成 proposal 中每个条件的
原始引用关系保持；审查仍可从一个展开记录核对所有引用这个来源的条件。

事件序号、artifact UUID 和 evidence UUID 分别计数，不把不同引用类型合并。
不存在的引用仍不产生正文，确定性门禁仍逐条拒绝无效引用。未裁剪独特的原始
证据，不改变自动审查开关、模型推理配置、审批、持久化或数据传输边界。

## 回归与验收

纯内存测试使用三个完成条件，覆盖重复事件/产物/证据、同 UUID 不同类型、
首次顺序、完整正文和源状态不变。修复前该用例展开 8 个记录，预期 3 个而失败；
修复后只展开 3 个独特记录，六个缺失引用仍被门禁全部标记为错误。

定向命令：cargo test -p omicsops-agent-core reviewer_materialization -- --nocapture。
最终运行默认完整测试、Web/Windows 桌面构建并记录于本次性能验证文档。
没有配置一次性真实 OpenCode 环境，模拟 payload 去重不证明真实耗时的降幅。

Windows 手工 smoke：在一次性项目中让同一论文工具结果支持多个完成条件，
保持自动审查开启，确认审查后答案、证据链接和条件覆盖完整；检查脱敏请求字节
计数，避免记录论文正文、模型私有推理或账户凭据。
