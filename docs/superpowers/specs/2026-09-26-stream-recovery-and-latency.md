# 不完整模型流恢复与运行耗时

## 实测问题

用户的 OpenCode Go deepseek-v4.1-flash/max 运行历时约 31 分钟，7 个工具批次
执行时间合计约 16.7 秒。6 个成功模型回合共输出 114,453 tokens，其中推理为
106,189（约 93%）；另两次模型调用中断，其中一次在约 643 秒后重试成功。
最后一次在约 123 秒后以无终止事件的流结束。上述统计仅使用只读运行元数据，
不保存用户提示词、原始工具输出或密钥。

## 断流恢复边界

解码器已接受有效 finish_reason 或协议完成标记；真正缺少终止事件时拒绝该响应
是正确行为。缺陷是桌面错误分类没有将解码器的固定缺终止事件错误归入已有的
临时传输故障，因而跳过了有界重试。修复只补全该错误分类，不伪造完成事件。

每次重试重新生成完整回复并使用新的收集器；旧响应中的半截文字与工具参数
不拼接、不执行。仍遵守现有重试次数、取消、完整请求预算和冻结配置，不修改
自动继续设置，不绕过工具审批，也不自动重放已经派发的外部工具。

本地模拟 SSE 回归应覆盖：第一响应缺终止事件、第二响应完整时只得到新调用；
重复 EOF 重试耗尽后零工具派发；有效 finish_reason 无需额外 DONE；截断输出、
拒绝和认证错误仍按原语义分类，不当作成功。

## 上下文性能改动

最新持久检查点的科学状态为 152,313 字节，其中历史 provenance.code 正文约
84,795 字节。每轮重复发送这些代码增加输入，且多数查询与证据整理不需要重读
完整脚本。参考项目的归档后按需读取策略：在 auto_compact 开启且已有结果读取
能力时，代码正文合计超过 16 KiB 即先归档完整快照，随后模型视图仅省略 code 键。
分析、数据、证据、有效性、参数和 code_sha256 原样保留；需要代码时使用真实
checkpoint 的 scientific_state 引用恢复。相同快照复用，不增加模型摘要调用。

优先用省略代码的视图拟合完整请求；仍超预算时采用现有目录视图。保留原始近期
工具步骤，按最终视图大小裁剪。无读取能力、关闭压缩时保持原语义。纯性能优化
归档失败、但原候选已合法时退回完整候选，不发送不存在的引用；原候选也超预算
时保留原失败语义。完整持久化证据与冻结配置不改。

这项变化减少输入，并不保证消除全部推理延迟。用户已选择 max；未经明确选择不
把它改成 low，也不承诺参考项目或本次修复能让任意长研究任务在固定时间内结束。
