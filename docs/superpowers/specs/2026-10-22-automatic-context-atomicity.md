# 自动上下文压缩的准入与原子提交

## 依据与目标

承接 `2026-10-22-wisp-run-identity-and-mcp-lifecycle.md` 的首项 P1。参考 Wisp Science 固定版本 `4f2957a309377bd605f9509b87361b6e10617575` 中 `crates/wisp-core/src/context.rs` 的失败恢复设计：摘要、检查点或预算失败时保留原工作上下文。OmicsOps 使用持久事件链，因此需要把这一原则落实为数据库原子性。

现有自动路径先使用临时归档身份预检，再分别写归档、Archived 和 Checkpointed；正式事件哈希改变后，完整请求可能被拒绝，但恢复投影已变化。原始事件未删除。本轮目标是失败不提交半成品，成功保存的事件与最终准入使用的事件完全一致。

## 边界与实现

- Core 预分配真实归档 UUID、时间和 SHA256，每次拟合检查点后重建精确 Archived / Checkpointed 链。最终完整模型请求（含原生 replay 闭合引用）通过准入后才能调用 Store；不发送模型请求来压缩。
- EventStore 使用必需的原子端口 `commit_context_compaction(spec, transcript, events)`，其中 `events` 为两个精确事件；不提供顺序写入的默认实现。错误区分来源/契约被拒绝与存储不可用。沿用现有事件和归档结构，不新增表、DTO 或手动压缩回执。
- Store 在 `BEGIN IMMEDIATE` 中核对运行归属、运行中状态、冻结 spec 和事件锚、完整来源事件链、科学快照及检查点准则。支持 OrdinaryAgent 和 ApprovedPlan；不借用手动压缩的 waiting_for_input 门槛，不修改批准计划或扩展授权。
- 恢复执行必须先在持有 driver lease 时完成 `start_agent_execution_v4`：事务内检查来源 head、状态、冻结身份、终态和停止请求，只将运行状态更新为 running。恢复后的自动压缩因此具有与新 Run 相同的持久状态；失败不登记为已启动，不能覆盖停止或终态。
- 在同一事务插入归档和两条事件，任一步失败整体回滚。成功后才发布桌面事件。Core 保留返回前的验证以及现有模型发送前的准入检查；并发来源变化返回错误，不自动重新派发任何工具或计算。
- 可选代码视图优化的存储不可用（数据库或 I/O 错误），只有原始完整请求已通过准入时可沿用原始上下文；来源/契约拒绝、强制压缩或预算不足时失败，保留原链。JSON 校验错误也归入拒绝，不通过错误文本猜测类别。
- 本地与 SSH 共用相同事件语义，不调用真实执行环境，不改变后台任务取消或重连行为。保留全部原始证据；凭据路径、MCP stderr、同 Run 调用 ID 冲突和 replay 裁剪不在本轮范围。

## 验证

使用 Core 模型替身、内存事件仓库和临时 SQLite。覆盖正式与预检事件引用相同、预算拒绝零写入、可选代码视图回退、归档与两个事件逐点失败回滚、来源 head / science / spec 变化拒绝、两种执行模式及数据库重开恢复。最终执行 Web 构建、Rust workspace 测试、前端测试和 Windows 桌面构建。真实模型与 SSH 验收另行记录，不以构建或测试替身宣称端到端验收。
