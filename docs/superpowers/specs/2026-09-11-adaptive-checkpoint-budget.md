# 按实际请求预算收缩检查点

## 根因

文献检索运行的检查点已经建立，但最近步骤占约 190 KB，科学状态约
38 KB 又随请求携带，最终上下文为 268851 字节，超过 262144 字节预算。
原实现固定保留最近若干事件，仅压缩一次；字符串内嵌 JSON 还会增加序列化
体积，因此单条结果有上限不代表检查点总量有上限。

## 行为

构建检查点后，验证实际序列化上下文及完整模型请求。若超限，从最旧的
recent_steps 开始逐项移除，再验证，优先保留最新执行信息。这个过程仅做
本地预算校验，不调用模型、不重复执行工具、不增加配置或模型上限。

冻结计划、完成标准、活动用户指导、任务状态、科学状态和错误信息不在此
裁剪范围。原始事件全文先归档，归档成功且检查点持久化后才返回模型上下文。
归档失败不改动事件链；不可缩减部分仍超限时继续明确暂停。

2026-09-22 后续修复：[失败委派的检查点错误预算](2026-09-22-failed-delegation-checkpoint-budget.md)
补足失败工具正文绕过短视图的路径。错误语义和原始事件继续保留；具备结果分页
读取能力时，检查点中的失败工具错误复用有界事件视图与原文引用。旧检查点的
`recent_steps` 已为空，但错误投影仍可改善时，允许重新生成一次检查点。

旧的超大检查点即使没有新增普通事件，也允许重新收缩。已达到最小检查点
而仍不可容纳的请求不反复归档。界面对 byte-budget 暂停提供现有的“继续运行”
操作，恢复同一个任务；不将其他 needs_attention 原因一概视为可安全恢复。

## 回归验证

- 从含 16 条大型近期输出的历史检查点恢复，同时满足 30 KB 应用预算与更小
  的完整模型请求预算，保留最新步骤、冻结计划、原始事件；二次读取不再次归档。
- 保留不可缩减请求停止、归档失败事件链不变、模型溢出单次重试等原有测试。
- 前端超限暂停可以调用同一 run ID 的继续运行动作。
