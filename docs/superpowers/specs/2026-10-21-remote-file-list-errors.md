# 远端文件列表失败与刷新状态

日期：2026-10-21。

## 问题与证据

SSH 文件面板在查询失败后同时显示远端命令错误和“远端目录为空”。原实现以空数组表示未加载、失败和确实为空，没有独立查询状态；失败消息又与传输提示共用状态。项目或 SSH 绑定切换后，旧请求也可能覆盖当前列表。

针对用户指定项目的只读诊断复现了原根目录校验返回退出码 1、stdout/stderr 均为空。进一步分步检查发现：SSH 认证正常，父目录存在且可读、可进入；绑定路径的存在性与目录检查失败，`find` 返回路径不存在。GNU `realpath` 可以为缺失的末级路径返回规范路径，所以不能把解析成功当作目录存在。历史成功传输记录不证明文件目前仍存在。

之后按用户确认的同一路径复查，父目录直属名称匹配、SFTP 元数据和 SSH 目录检查均已成功，文件枚举退出码为 0、可见条目为 0。前后观察不同，不能把旧错误缓存为当前目录状态，也不能推断目录恢复后历史文件自动存在。

以上是指定连接的只读故障诊断，不是一次性环境中的真实 SSH 端到端验收。诊断没有创建目录、修改远端文件或修改项目绑定。不能据此切换服务器、重新上传旧文件或重新执行科研流程来掩盖问题。

## 行为

- 文件列表区分 `idle`、`loading`、`ready`、`error`，只有成功读取且结果为空时显示空目录。
- 查询错误与传输提示分开。刷新开始及成功时清除旧错误类别；失败显示可重试提示。已成功读取的同一绑定列表可以保留，错误提示仍明确可见。
- 请求身份包含项目 ID、连接 ID、远端根目录和请求序号。切换绑定、移除绑定、卸载、较新请求完成后，旧请求均不能更新列表。
- 远端根目录先执行 `realpath`，严格解析单一绝对路径，再独立验证目录。保留合法路径空格，拒绝启动噪声、多行、相对路径及控制字符。
- 根解析、目录验证和扫描错误分别使用 `remote_root_resolution_failed`、`remote_root_unavailable`、`remote_listing_failed`。前端仅识别白名单类别，提供中英文说明，不把原始远端输出作为提示。
- 文件扫描真正跳过 `.omicsops` 子树，避免进入内部环境或控制目录后因权限问题破坏列表。其他扫描失败仍拒绝部分结果。
- 列表查询成功或失败均尝试断开 SSH；断开失败不能覆盖最先发生的查询错误。

不新增数据库表、持久化字段或 DTO；不修改凭据、主机指纹、项目绑定、冻结运行身份、审批、上传下载与后台作业语义。
