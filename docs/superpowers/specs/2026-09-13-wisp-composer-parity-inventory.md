## 纠正前一版方案

1. 闪电是 Fast 服务档位，启用时可写入 `priority`；不是 Agent/Plan 模式切换。只对支持的配置显示，区分配置默认值和会话覆盖，执行中禁止修改。
2. 发送下拉不是“直接执行／先做计划”。它提供侧边问答、分支会话，以及运行中追加指导和中断替换；运行中普通发送会排队，并有独立停止按钮。
3. 请求审核实际调用 `review_session`，不是在输入区放一句“请审核”。
4. “保存为技能”在参考 UI 中实际先预填技能生成请求，恢复输入焦点；点击本身不声称已经写入技能文件。
5. 分享不止图片，展开后还有消息选择、脱敏、PNG/HTML 和 PNG 宽度。
6. `/` 不止 Skills，还包括内置命令和工作流模板。

## 建议架构与分批交付

这是跨 UI、DTO、持久化和运行生命周期的架构变更。采用“按功能闭环分批实现，最终逐项验收”的方案。只做前端开关不满足要求；整体复制 Wisp 会破坏本项目 V4 的授权与恢复约束。

1. 输入区外观、菜单状态、分享、保存技能入口和模型推理强度；每个入口只在对应真实行为实现后完成。
2. 类型化引用解析、搜索目录、Skills/工作流选择和 Ctrl+K；宿主校验来源与作用域。
3. 会话设置持久化与冻结运行配置：委派、记忆、审核及模型/专家/Fast；重用现有 reviewer 和 role 绑定。
4. 排队、指导、中断替换、侧边问答和分支；统一幂等派发与恢复测试。
5. Background 委派完成/续跑、失败分析、上下文统计/压缩、撤销和轨迹；完成其余命令。
6. ACP 会话配置与 WSL/多计算资源适配；合并交付前消除清单中的未完成项。它们是本次完整范围，分批不表示豁免。

UI 的不同入口共用同一操作，避免 `/review` 与菜单 Review 实际走不同逻辑。跨边界类型进入 `omicsops-dto` 并补 DTO 契约测试；保存层迁移幂等、旧配置默认兼容。新增会话偏好用于下一次运行，已冻结运行的 role、资源和授权不随菜单改变。排队消息/分支关系/后台完成收据只有在需要跨重启恢复时才新增持久化实体。

## 验收方式

- 为上面 64 个验收项维护实现位置、自动化检查、实际结果和手工验证状态，不用菜单存在或禁用占位判定完成。
- 所有覆盖层打开后立即对 window 按 Escape，无需内部聚焦；一次只关闭顶层，子菜单关闭后父菜单保留。覆盖分享、模型强度、计算、专家、搜索、上下文和撤销预览。
- 中文 IME、窄窗口、草稿失败保留、异步陈旧结果、跨会话切换、保存失败回滚、旧会话恢复都需测试。
- 运行相关检查使用模拟 provider、模拟进程/SSH、临时数据库；覆盖中断不确定、重复派发、重启消费与权限边界。
- 分享验证实际导出文件、HTML 安全和 PNG 可读布局；用户取消不生成成功消息。
- 默认完整检查：`cargo test --workspace`、`npm test`、`npm run build`；桌面组合变更加 `npm run build:desktop`；锁文件变化加 `npm ci`。
- 真实 ACP/WSL/SSH/模型验收按 `acceptance/README.md` 单列实际命令和结果；未执行不能写为通过。
