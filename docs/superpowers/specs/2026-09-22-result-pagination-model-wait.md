# 工具结果分页与模型等待可见性

## 问题与证据

一次实际运行在工具验证成功后连续读取三页历史结果，随后长时间没有可见回复，最终由用户取消。持久化事件显示：

- 约 105.024 秒时，三个读取已完成；原始结果为 19,005 字节，页偏移为 0、8,192、16,384。
- 前两页各包含最多 8,192 字节内容，但加上 JSON 转义和分页元数据后，模型结果字段分别为 8,466 和 8,440 字节。
- 105.055 秒时启动下一次模型请求，序列化请求为 164,414 字节；模型为 `glm-5.3`，未设置 reasoning effort。
- 238.228 秒记录 interrupted、未知用量；238.233 秒记录用户取消。因此最后一次模型等待约 133 秒，尚未达到现有 180 秒单次请求期限。

代码确认两个独立问题。`read_result` 按内容字节分页，`read_outcome` 再将其包装为 JSON；`event_view` 对包装后的结果再次应用 8,192 字节限制，导致已读取页面又被截断，且恢复引用指向本次读取事件。另一方面，界面没有区分模型等待与工具执行，运行时长取最新事件时间，模型等待期间数字不再变化。

现有证据不能说明模型服务内部为何等待，也不能证明再次截断直接造成该次延迟。成功的产物验证不等于已提交完成答案；取消也不等于模型超时。

## 最小行为变化

### 可完整消费的分页

保留同一运行、项目、会话和事件哈希的读取校验，以及 UTF-8 边界和 `next_offset` 语义。分页响应必须在经过真实模型投影后仍保留完整页面内容和分页元数据，不再要求模型读取“读取结果”的原文才能恢复本页。

在序列化预算内选取页末尾，允许实际页长小于调用者指定的上限。调用者按返回的 `next_offset` 继续读取；最后一页为 `null`。不能只缩小固定内容上限，因为 JSON 转义开销随内容变化。持久化的原始工具证据保持完整。

### 显示模型等待

利用已有模型请求与用量事件识别当前 attempt。请求开始后显示等待模型响应和实时等待时长；有流式文本预览时显示正在生成回复。匹配 attempt 的 final/interrupted 用量结束等待，partial 用量不结束；旧请求的迟到记录不能清除新请求。

完成的模型文本、周期结束、工具执行、暂停或终止等后续边界不能留下过期等待状态。历史运行不展示活动计时器。计时器在结束、切换运行或卸载时清理。重试事件本身不足以推断新的模型请求，因为 reviewer 也使用该事件。

## 边界

不修改 180 秒请求期限、重试次数、取消或远端计算生命周期。不自动重新派发计算，不将等待视为失败，不在取消后伪造完成答案。宿主审批、冻结计划、凭据存储、运行隔离和审计校验保持现有语义；不引入新的外部数据传输路径。模型请求仍可能包含既有结果和元数据，不能据此声称数据始终留在本机。

## 验证策略

- 后端测试覆盖原始结果 → `read_outcome` → 持久化事件 → `event_view` 的真实路径，而不仅直接调用 `read_result`。覆盖满页、JSON 引号与换行、多字节 UTF-8、完整重组与最后一页。
- 前端使用模拟事件和计时器，覆盖等待时长持续增加、预览生成状态、匹配/不匹配 attempt、partial/final/interrupted 用量、工具边界、暂停、取消、历史记录和卸载。
- 先运行相邻 Rust 与前端测试，再执行仓库完整检查：`cargo test --workspace`、`npm test`、`npm run build`。实际命令与结果由交付记录补充。

手工 smoke：在 Windows 桌面查看等待中的模型请求，确认没有新事件时等待秒数继续增加；取消后立即停止等待展示，已有工具证据仍可查看。读取包含多字节文字、引号和换行的大结果，确认模型可顺序读取全部页面，且不产生递归恢复引用。

本次确定性测试不依赖真实模型、SSH、GPU 或科研数据，也不证明真实服务延迟已消除。真实 Agent/SSH 验收须在确定性检查后按 `acceptance/README.md` 使用一次性环境显式执行并单独报告；未执行的 live acceptance 必须标记为未执行。
