# Conversation MCP grants and bundled client refresh

Observed local run events contained a missing readOnlyHint and HTTP 400 errors from the old bundled client. The configured PubMed command pointed at target/release while the updated app ran from target/timeline-desktop/release. The configured tool names alone did not make their effects read-only.

- Bundled PubMed now advertises readOnlyHint=true for both tools. Before discovery, an enabled, launch-approved bundled profile with the exact built-in argument and OmicsOps executable name is refreshed against the currently running executable when its path or read-only metadata is old. The host inspects the replacement, stores its catalog, clears old per-tool grants, and retains the existing launch approval. Third-party commands are not rewritten. Existing credentials remain vault references.
- Explicit MCP approval is reused in the same project/conversation for the same server and exact tool catalog, including subsequent tool names/queries from that catalog. The original approval decision and frozen source-run hash are validated. Cross-conversation, changed catalog, disabled server and revoked launch approval cannot reuse the grant. Each invocation still checks the chosen tool schema. The approval card explains this scope. RiskBased remains automatic for eligible read-only tools.
- Two returned MCP business errors from a server stop further dispatch to it in that run. A success resets the failure count. Pre-dispatch validation failures do not count. When all discovered servers are blocked, the generic invocation wrapper is removed from subsequent model requests. Existing evidence is retained and the model is instructed to report the blocker or use another available server, without guessing PMIDs or repeating directory discovery.

Tests cover conversation target scope, PubMed annotations, the failure limit, and the existing authorization and dispatch boundaries. Live bundled-MCP smoke is distinct from a full model-driven Agent acceptance test. Users must close older app instances before starting the updated executable so old processes do not continue using old logic.

Executed: cargo test --workspace (419 passed, 11 ignored), npm test (149 frontend + 22 extension passed), npm run build, and npm run build:desktop (passed). A live JSON-RPC smoke against the rebuilt bundled MCP queried `liver cancer single cell` with limit 2: both without a key and with an intentionally invalid test key returned isError=false, total 13904, and PMIDs 42721975 / 42720825. Both advertised readOnlyHint=true. The restricted-network attempt could not send the request; the authorized network probes passed. No real credential was read or logged by the probe. Full model-driven Agent acceptance remains unexecuted.
