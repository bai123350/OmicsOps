# MCP 目录绑定与运行收尾

## 实际故障

失败记录包含漏填 schema_sha256、多次误写 catalog/schema hash，以及一次超长
PubMed 查询。服务端当前目录与发现目录一致，前两类属于模型复制元数据错误。
主循环持续追加检索，耗尽轮次后未调用 agent.complete。

## 行为

- 新生成的 MCP 调用在记录和审批之前，按 server_id/tool 精确匹配本轮成功
  search_mcp_tools 事件中的目录，绑定该快照的两个哈希。模型可省略哈希。
  不改变工具目标或业务参数，不获取最新目录覆盖冻结值；实际服务端变更仍
  被执行边界拒绝。未知目标不补全。已记录/已批准的旧调用不改写。
- 普通 Agent 的长轮次预算（至少 8 轮）预留最后 4 轮用于整理、证据登记和
  完成。系统提示明确要求收尾，同时隐藏并拒绝追加检索、技能发现和委派。
  读取已有证据、产物整理、提问及 agent.complete 保留。
- 已因 MissingCompletion 耗尽轮次的旧任务恢复后直接进入收尾，不重新消耗
  一轮检索预算。此行为有实际主循环恢复测试。
- 不扩大轮次，不伪造完成调用，不跳过证据核验。确实缺少必要证据时要求
  明确说明 blocker；真实目录变化、服务端故障和非法查询仍可返回失败。

## 验证

测试覆盖错误/缺失哈希的快照绑定、未知目标不变、查询参数不变，收尾阶段
工具可用性，以及普通主循环在耗尽轮次之前进入收尾并通过完成校验。
真实模型科研任务验收未执行；成功的确定性完成测试不等于生产端到端完成。

验证记录：Rust workspace 427 通过、11 ignored；前端 151、扩展 22 通过；
Web 构建通过。
