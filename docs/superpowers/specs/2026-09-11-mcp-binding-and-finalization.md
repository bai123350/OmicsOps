# MCP 目录绑定与运行收尾

> 历史说明：本文的预留四轮、预留十二次调用及旧失败任务直接收尾机制，
> 已被 [普通 Agent 迭代预算与到限总结](2026-09-12-agent-iteration-summary.md)
> 替代；相关旧测试已改为新行为测试。MCP 目录绑定与失败栏移除继续有效。

## 实际故障

失败记录包含漏填 schema_sha256、多次误写 catalog/schema hash，以及一次超长
PubMed 查询。服务端当前目录与发现目录一致，前两类属于模型复制元数据错误。
主循环持续追加检索，耗尽轮次后未调用 agent.complete。

## 行为

- 新生成的 MCP 调用在记录和审批之前，按 server_id/tool 精确匹配本轮成功
  search_mcp_tools 事件中的目录，绑定该快照的两个哈希。模型可省略哈希。
  不改变工具目标或业务参数，不获取最新目录覆盖冻结值；实际服务端变更仍
  被执行边界拒绝。未知目标不补全。已记录/已批准的旧调用不改写。
- 普通 Agent 的长轮次预算（至少 8 轮）预留最后 4 轮用于整理、证据登记和
  完成。系统提示明确要求收尾，同时隐藏并拒绝追加检索、技能发现和委派。
  读取已有证据、产物整理、提问及 agent.complete 保留。
- 已因 MissingCompletion 耗尽轮次的旧任务恢复后直接进入收尾，不重新消耗
  一轮检索预算。此行为有实际主循环恢复测试。
- 不扩大轮次，不伪造完成调用，不跳过证据核验。确实缺少必要证据时要求
  明确说明 blocker；真实目录变化、服务端故障和非法查询仍可返回失败。

## 验证

测试覆盖错误/缺失哈希的快照绑定、未知目标不变、查询参数不变，收尾阶段
工具可用性，以及普通主循环在耗尽轮次之前进入收尾并通过完成校验。
真实模型科研任务验收未执行；成功的确定性完成测试不等于生产端到端完成。

验证记录：Rust workspace 427 通过、11 ignored；前端 151、扩展 22 通过；
Web 构建通过。

## 2026-09-12：调用预算先于轮数耗尽

截图显示运行以 tool-call budget exhausted (96) 中止。主循环原先仅按轮次
触发收尾，并行调用可在收尾前用完调用额度；同一批次在超限处直接返回，
还会留下已记录但尚未派发的请求。

普通 Agent 现在按轮次和累计 ToolRequested 数任一阈值进入收尾。调用预算
预留 min(12, max(1, floor(max_tool_calls / 4))) 次（不超过总额度），默认
96 次中最多 84 次可用于收尾前的检索。阈值也在批次内逐次检查：超出检索
额度的调用记录明确拒绝结果，不派发、不占用预留额度；已接受调用继续完成。
预留额度仍受原有总上限约束，不保证不遵循收尾要求的模型一定完成。
该策略适用于普通 Agent；冻结计划的执行能力与审批范围不变。

UI 保留每次调用的真实审计记录，MCP 行额外显示实际工具名和已脱敏的查询
摘要。删除失败/上下文预算诊断后的通用红色“继续运行”栏；保存结果恢复、
浏览器连接及人工处理入口继续可用。已有失败记录不会被改写成成功。

回归测试覆盖少于八轮时的调用预算收尾、84/100 次单轮检索、已接受调用都有
成功结果及最终核验完成；前端覆盖 MCP 摘要、失败栏移除和保留恢复入口。
Windows 手工 smoke：运行一次文献检索，检查工具摘要及最终输出；查看历史
失败记录确认红框消失；连接浏览器后的同任务恢复仍可用。真实模型/MCP
检索与桌面手工 smoke 尚未执行，截图内个别 MCP 失败的具体错误无法由折叠
行确定。无需模式迁移，不改凭据存储、审批裁决、隔离或数据传输边界。
