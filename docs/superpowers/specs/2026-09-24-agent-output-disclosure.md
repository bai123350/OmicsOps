# Agent output disclosure

The V4 conversation keeps public progress inside the execution timeline and the final answer as a separate assistant message. The compact timeline orders model requests, public progress, and tool calls by event sequence. A public progress row shows its first nonblank line; its Markdown body starts folded. Every tool body starts folded, including running and failed calls. Its summary keeps the real tool name, available input subject, status mark, duration, and settled output line count visible. A historical or cancelled tool without a finish event has no invented completion duration.

This uses the live-tool disclosure and Markdown progress pattern in [wisp-science's chat renderer](https://github.com/xuzhougeng/wisp-science/blob/main/ui/src/chat_render.rs) as a reference. OmicsOps keeps its existing evidence cards.

The 2026-09-25 follow-up adds a live plain-text THINKING row only for reasoning that an external provider actually streams for the current request. It replaces that request's MODEL REQUEST row, starts folded, and uses a bounded, host-redacted, run-and-attempt-scoped transient channel. It never becomes public Markdown progress or a final answer, and past model requests are never given invented thinking text. The current request or tool state and elapsed wait remain visible in a quiet status line outside the folded timeline. The clock changes only the displayed duration; it does not count as provider activity or suppress the 90-second silence warning. When no reasoning bytes arrive, the timeline records MODEL REQUEST and the status line says it is waiting for model content. Approval and user-input pauses do not present the agent as actively working.

Earlier activity still folds after six items. The Processed/Processing heading reports total run duration. The final answer gets a thin separator, an OMICSOPS label, the actual message timestamp when available, and serif Chinese prose styling; no timestamp is synthesized when one was not saved. Tool input and output continue through the existing redaction and evidence presentation paths. Reasoning preview is transient UI only and creates no audit events.

For the 2026-09-25 output styling follow-up, `cargo test --workspace` passed (1,299 passed, 12 ignored), `npm test` passed (893 Vitest and 22 browser-extension tests), and Web and desktop builds passed. An Edge visual check used the actual WorkspaceShell with synthetic current and completed event sequences: THINKING began folded, expanded on request, and disappeared when the scene changed to a content-free request; the 600px viewport had no document overflow. This visual check did not contact a live provider, and no fresh API or SSH acceptance run was performed for this presentation-only change.

Its first run in the restricted sandbox failed credential preflight in 0.01 seconds, before any model request. Running the same test in the normal Windows user session passed (1/1, 15.15 seconds, exit 0): the model read the temporary file through the Agent tool and returned the nonce in its final response. This validates that narrow model-to-tool-to-final path. It does not validate literature research, SSH, or live GUI activity and disclosure behavior.
