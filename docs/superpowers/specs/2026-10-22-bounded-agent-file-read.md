# Agent project.read 有界文件读取

## 问题与参考

变更前，`project.read` 只限制显示行数。本地实现先用 `read_to_string` 读取整个
文件，再取前 400 行；SSH 实现通过 `sed -n '1,400p'` 返回内容，单行没有字节
上限。大型科学文本、超长单行或没有换行的文件因此仍可能造成无界读取、传输
和结果分配。400 行不能独立构成内容大小上限。

参考对象固定为 Wisp 提交
[`4f2957a309377bd605f9509b87361b6e10617575` 的 `crates/wisp-tools/src/read.rs`](https://github.com/xuzhougeng/wisp-science/blob/4f2957a309377bd605f9509b87361b6e10617575/crates/wisp-tools/src/read.rs)。
本变更采用同时约束行数和字节数的理念；下述 64 KiB 预算、400 行上限、项目
路径政策和 Local/SSH 边界由 OmicsOps 确定，不宣称与上游行为完全相同。

## 范围

仅调整 Agent 的 `project.read`：

- 本地和 SSH 使用相同的文本投影与显示上限。
- 保留两端各自已有的项目路径、普通文件和符号链接政策。
- 读取失败继续产生现有脱敏的、可恢复的项目文件查询失败结果。
- 工具描述明确返回有界文本，截断结果明确说明它只是文件前缀。

不调整 `project.list`、`artifact.verify`、表格预览、Composer 文件引用或
`read_optional` 项目规则读取。`AGENTS.md` 和 `.omicsops/AGENT.md` 的提示层
读取另属现有路径，不能把此次修复描述为所有项目文件读取均已有界。

不新增 DTO、数据库表、迁移、审批流程、权限或持久化类型。现有工具结果仍由
原来的事件和结果路径保存；不重写历史结果，不新增后台作业或自动重试。

## 读取和显示契约

宿主固定原始内容预算为 64 KiB，即 65,536 字节。每次最多读取 65,537 字节，
最后一个额外字节只用于探测 EOF，不进入返回内容。即使文件只有一行，也必须
遵守同一读取上限；不先完整读取、解码或传输，再截断已分配内容。

- 实际 EOF 位于预算以内，或恰好位于预算处且额外探测返回 EOF，可以认定
  原始读取已到文件尾。
- 额外探测得到字节，表示原始读取是前缀；该字节必须丢弃。
- 文本投影最多显示 400 个文件内容行。提示不算文件内容行，但计入结果字节
  预算。
- 最终返回字符串的 UTF-8 字节总数不得超过 65,536，包括开头的截断提示、
  分隔换行和内容。
- 原始字节、行数、UTF-8 尾部半字符或最终显示预算造成省略时，都必须添加
  开头提示，明确“这是文件前缀，不是完整文件”。先为提示预留空间，再在合法
  UTF-8 边界内保留内容；不能追加提示后突破上限。
- 小文件在没有内容省略时不添加截断提示。空文件返回空字符串。

显示内容始终来自文件开头，不拼接文件尾部。这里不能复用保留首尾、删除中段
的 `bounded_excerpt` 语义。该结果是经过换行规范化的文本投影，不是原始字节
快照，也不提供整文件哈希。

## 编码与换行

两端共享严格 UTF-8 投影。先验证实际保留的原始前缀，再处理行数和显示预算：

- 合法 UTF-8 正常处理。
- 只有已知不是 EOF 的前缀，在末尾出现不完整 UTF-8 字符，并且
  `Utf8Error::error_len()` 为 `None` 时，可以回退到 `valid_up_to()`；回退后
  的结果必须标记为前缀。
- 完整文件的尾部不完整字符，以及读取范围中间的非法 UTF-8，都返回读取失败。
  不使用替换字符伪装成成功读取，也不通过先截取 400 行来隐藏已读取字节中的
  编码错误。
- 未读取的文件后缀没有经过编码验证；成功返回前缀不能证明整文件是合法
  UTF-8。

CRLF 归一化为 LF，去掉结果末尾的行终止符，沿用原 Local 的
`lines().take(400).join("\n")` 语义，保留该语义下的内部空行。

这会明确改变原 SSH 的行为：原 SSH 命令输出使用有损 UTF-8 解码并保留末尾
换行，改后与 Local 共享严格解码和换行规范化。原 Local 对整个文件做编码
验证，改后仅验证受预算限制的读取范围；这是有界读取的预期边界。

## Local 与 SSH 实现边界

Local 保留 `LocalProjectFilesystemV4::resolve_existing` 和现有普通文件
检查，使用打开的文件句柄执行预算内读取。不能直接套用 Composer 的路径
规范化政策，否则会额外禁止 Agent 原本可读取的项目内部路径或祖先链接。
本变更不因复用接口而扩大或缩小现有项目范围。

SSH 保留当前 `project_path`、`resolve_existing` 和项目根目录包含检查：

1. 对尚未被 `realpath` 消除链接的 raw 路径保留 `test ! -L`。
2. 对解析后的 canonical 路径保留 `test -f`。
3. 对该 canonical 路径调用现有 `SshSession::read_file_prefix`，预算为
   65,536 字节；使用它返回的原始 bytes 和 EOF 状态进行共享文本投影。

检查命令的路径继续使用现有 shell quoting。SFTP 不可用、文件检查失败、
读取失败或检测到源变化时，返回现有脱敏失败结果，不回退到无字节上限的
`cat`、`sed` 或其他 shell 读取，不重新派发读取。

现有 SFTP 前缀接口在同一打开句柄前后观察 size/mtime；可观察到变化时拒绝
结果。缺少元数据时不能补成零或宣称稳定，元数据相同也不证明原子快照、完整
源身份或内容哈希。现有路径检查到打开文件之间的并发竞态不因本变更而消失。

## 宿主结果与工程边界

生产入口位于 `src-tauri/src/agent_v4.rs` 的 Local/SSH 文件系统和
`project.read` 分支；工具说明位于 `crates/omicsops-tools/src/lib.rs`。
SSH 原始读取复用 `crates/omicsops-adapters/src/ssh.rs`，不建立第二套传输
实现。需要测试替身时，仅为读取涉及的 SSH 检查与前缀调用保留窄注入接缝。

失败仍通过 `failed_project_file_query` 返回，不能把 OS/SSH 原始错误、绝对
路径或服务器输出放进模型内容和公开结果。该工具仍受冻结项目和执行后端
约束；不改变凭据存储、宿主审批裁决、隔离或恢复语义。

成功结果仍可能进入模型上下文和既有事件记录；有界读取不等于数据永远不离开
本机，也不使读取内容自动成为科学结论或整文件验证证据。

## 自动化验证

测试使用临时目录、内存字节源和 SSH 检查/读取替身，不要求网络、真实 SSH
主机、Python/R 或模型凭据。至少覆盖：

- 空文件、预算内文件、恰好预算并确认 EOF、预算加一、巨大单行和超过 400 行。
- 输出包含截断开头提示时仍不超过 65,536 字节，且内容只取自起始前缀；
  400 行以内的小文件不被错误标记截断。
- CRLF、末尾换行、内部空行、中文和 emoji；字节边界截断半字符可以回退，
  EOF 半字符和中部非法 UTF-8 必须失败。
- 既有项目文件系统测试继续覆盖相对路径、根路径拒绝、父级穿越和失败脱敏；
  本变更不改写路径解析或链接政策。
- SSH mock 验证 raw 路径 `test ! -L`、canonical 路径 `test -f` 的顺序、
  传给 SFTP 的 canonical 路径以及固定字节预算；检查失败不读取内容，读取
  失败没有 shell 内容读取回退或自动重试。项目包含检查仍由原解析入口负责。
- SSH 适配层现有测试覆盖 EOF 探测和同一句柄前后的元数据变化；mock 验证
  读取错误向上传递。执行与计划入口测试覆盖截断提示、保留原 provenance，
  以及编码失败产生无 provenance 的脱敏失败结果。

先执行与变更相邻的 Rust 测试，再执行仓库默认完整检查。干净检出先生成 Web

## 手工 smoke 与真实验收

Windows smoke 使用一次性本地项目和合成文本：启动构建后的应用，冻结 Local
后端，请 Agent 读取小型 CRLF 文件，再读取超长单行及超过 400 行的文件。
检查小文件内容、超限结果的开头提示和结果字节数，确认工具返回后对话仍可
继续。读取非法 UTF-8 和项目外路径时，应得到脱敏失败结果。不要用真实科研
样本或凭据验证大小限制，也不要把成功构建视为完成这些 GUI 步骤。

SSH smoke 必须先按 `acceptance/README.md` 配置一次性、受信任的远端环境，
冻结所选 SSH 后端后读取同类合成文件；检查末级符号链接被拒绝、解析后越界
路径被拒绝，既有允许的项目内路径行为不变。仅在专门准备的测试服务上验证
SFTP 不可用场景，确认返回失败且没有 shell 内容读取回退；不要修改共享或
生产 SSH 服务的配置。测试替身通过不能替代这项真实传输检查。

真实模型、真实 SSH 和 Windows GUI smoke 当前均未执行。后续执行须记录实际
命令、环境范围和结果，区分通过、失败、未执行与 ignored；不以 deterministic
测试或局部 smoke 宣称完整生产端到端验收。此文档也不对未验证的 macOS 路径
或安装包作兼容性保证。
