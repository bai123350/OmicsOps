# Agent V4 模型轮次超时边界

> 日期：2026-09-21
> 状态：已实现

普通 Agent V4 主生成使用两个边界：连续 180 秒没有真实流内容即触发空闲超时；
单次模型尝试最长 15 分钟，即使持续输出也会触发硬超时。非空的公开文本、推理
增量或实际工具调用名称/参数增量会刷新空闲计时；空内容、SSE heartbeat、usage、
provider retry 和仅供界面显示的活动状态不会刷新。超时错误区分空闲与硬上限，
并包含已等待时间或距最后一次真实内容的时间，不包含模型负载。超时后的不完整
工具调用不会被派发。

V4 主生成的流式 HTTP 请求单独使用 15 分钟总上限，连接上限仍为 15 秒；
普通 provider 调用、probe、reviewer、side-chat、非流式 fallback、delegated
模型调用、iteration summary 和 checkpoint 等流程继续使用原有 180 秒上限。适配器内部重试仍受
同一次主生成尝试的宿主硬上限约束，不因每次 HTTP 重试重新获得 15 分钟；
宿主在一次尝试失败后按既有 `max_model_retries` 策略启动的新尝试有自己的时限
和请求事件。这里选择有界
总时限，是受 [Wisp 的流式传输实现](https://github.com/xuzhougeng/wisp-science/blob/79e64163262196611dd390d06713c465b906b299/crates/wisp-llm/src/provider.rs#L357-L366)
启发：其客户端使用连接超时与 300 秒读取超时，并说明总请求超时曾截断仍活跃的
SSE 流。本项目的 180 秒真实内容空闲计时由 Agent 宿主执行，额外保留 15 分钟
硬上限；数值和是否有总上限均不等同于 Wisp。

这个边界只约束模型请求，不改变工具执行、远端作业或 shell 的超时。取消和新
guidance 仍以 50 毫秒轮询边界中断等待；模型重试数、Agent iteration、工具调用
预算和 delegated budget 继续独立生效。模型超时只终止当前模型等待，不把已派
发的远端计算记为已取消，也不会自动重放副作用工具。

调用方仍可为确定性测试或特殊的有界子流程显式设置更短的
`model_attempt_timeout`；对普通主生成，它是空闲时限，对其他流程仍是绝对时限。
真实模型 acceptance 使用生产默认值，避免由测试专属覆盖掩盖桌面组合中的
配置差异。新边界不能证明此前失败的请求是否曾有持续推理增量；需要看该次实际
流事件才能判断。
