# OmicsOps 生命科学桌面工作台重构计划

## 7. 2026-08-11 阶段 3 开发进展

本轮已经完成以下可运行链路：

- 桌面文件面板只通过“选择上传文件”入口建立显式上传清单，不扫描或隐式上传整个本地工作区。
- 通过现有受信任 SSH 连接索引远端项目目录，并排除 `.omicsops` 控制目录。
- 使用 SFTP 上传所选文件；上传后比较本地与远端 SHA-256，并将结果写入 schema v3 同步记录。
- 远端文件按需下载，使用临时文件、流式 SHA-256 校验和原子重命名。
- 本地存在不同内容时保存为 `.conflict-N` 并列版本，不静默覆盖原文件。
- 下载路径会检查项目根目录和符号链接边界，大文件校验采用 1 MiB 分块读取。
- 文件操作通过稳定的 `artifact-event` 通知桌面端；界面显示上传、刷新、下载、校验和冲突状态。

仍待阶段 3 后续实现：

- PDF、CSV/TSV、Jupyter、H5AD 与 Seurat 元数据真实预览器。
- Notebook 自动采集假设、方法、观察、决策、证据和代码。
- Notebook 的 Markdown、JSON 和项目打包导出界面。

## 1. 项目目标

将 OmicsOps 从五步远端执行向导升级为 Windows-first、仅桌面端的生命科学研究工作台：

- 采用“项目/会话 + 科研对话 + 文件/预览/实验记录”三栏布局。
- 保留并强化现有 Rust SSH、审批、策略、审计、验证和恢复底座。
- 支持生命科学数据分析、文献检索、图表与报告。
- 采用本地工作区加远端 Linux 计算，禁止隐式全量同步。
- 参考 InternAgentS、K-Dense BYOK、OpenAI4S 和 ClaudePrism 的产品模式，但不复制其实现。

首版不包含网页服务、在线技能市场、订阅 OAuth、全量科学格式支持，以及 macOS/Linux 正式发行。

## 2. 已锁定产品原则

- 默认中文，可切换英文。
- 本地工作区保存文献、笔记、脚本和选定产物。
- 大型计算默认在远端 Linux 完成。
- Tauri 只通过 `invoke` 和事件通信，不启动本地 HTTP 服务。
- 凭据只保存在 Windows Credential Manager，数据库和项目文件仅保存凭据引用。
- 模型、工具、MCP、文件写入和远端执行都必须经过能力声明、策略判断、审批和审计。
- 探索代码只有显式固化为版本化正式步骤后，才能进入正式产物和报告。
- 本地文件只允许选择性上传；冲突生成并列版本，禁止静默覆盖。
- GitHub 对标项目仅用于产品与架构参考；引入外部代码或技能前必须单独检查许可证、版本和安全性。

## 3. 核心接口与架构

### 3.1 领域模型

`omicsops-core` 使用以下工作台实体：

- `Project`
- `Conversation`
- `Message`
- `AgentTurn`
- `ToolCall`
- `Approval`
- `Artifact`
- `NotebookEntry`
- `SkillPackage`
- `ModelProfile`
- `SyncEntry`

正式任务继续使用 `AnalysisPlanV2`、`PolicyEnvelope`、V2 验证器和执行器。

### 3.2 Agent 编排层

独立的 `omicsops-agent` 提供：

- `AgentSession`
- `ToolRegistry`
- `ApprovalGate`
- `SpecialistDispatcher`
- `ModelProvider`
- `KernelSession`
- 探索代码到正式步骤提案的固化接口

编排层不得直接读取凭据或操作 SSH。凭据由适配层读取，远端执行继续由现有 runner 和 SSH 适配器负责。

### 3.3 模型提供方

统一支持：

- Anthropic Messages API
- OpenAI-compatible Chat Completions
- Ollama 本地模型

不同提供方的文本增量、工具参数增量和结束事件必须转换为同一 `ModelStreamEvent`。

### 3.4 科研数据源与 MCP

原生科研源：

- PubMed
- Europe PMC
- Crossref

每次检索保存查询、来源、标识符和检索时间。MCP 首版只接受本地 stdio，HTTP transport 不在首版范围内；启动 MCP 必须审批并记录审计事件。

### 3.5 探索内核

Python/R 远端探索会话采用 JSONL 协议，支持：

- 项目级持久会话。
- 流式 stdout/stderr。
- 保存代码单元和捕获产物。
- 断线后标记 `interrupted`。
- 只从已保存代码单元重建。
- 已保存代码计算 SHA-256，并以显式版本固化为正式步骤提案。

### 3.6 桌面通信

稳定事件名称：

- `conversation-event`
- `agent-event`
- `kernel-event`
- `artifact-event`

不得为桌面 UI 启动本地 Web API。

### 3.7 数据库存储

SQLite schema v3 使用规范化项目、会话、消息、Agent 回合、审批、产物、Notebook、技能、模型和同步表。

- 从 schema v2 迁移前创建 `.v2.bak`。
- 从更旧版本迁移时保留 `.v1.bak`。
- 迁移必须在事务中执行；失败时旧数据库保持可恢复。
- 旧 V1/V2 计划、运行、日志和审计只读保留。

### 3.8 本地与远端工作区

本地项目包含普通文件和 `.omicsops/project.json`。远端继续使用现有控制目录。同步清单记录：

- 相对路径
- 方向
- 大小
- SHA-256
- 状态
- 冲突版本

同步清单必须是显式选择集合，不得通过扫描本地目录自动扩大上传范围。
